# Production live test report — 2026-08-09

Target: `https://kampung-quest-production.up.railway.app`

Method: Playwright Chromium, fresh browser contexts, read-only checks unless required for authentication. The live database was not reset and no quest, message, invitation, preference, reward, or task mutation was submitted.

## Prerequisites and environment

- Live `/health` endpoint was reachable over HTTPS.
- PostgreSQL, pgvector, embedding index, and Gemini all reported ready.
- Viewports tested for public surfaces: 1440×900 and 390×844.
- Authenticated matrix prerequisites were not met: the documented QA accounts `sqtest.garden.host` and `sqtest.garden.walk`, plus their documented email identifiers, all returned a safe 401 with the shared fixture password. No production account was created to bypass this blocker.

## Results

| Area | Result | Evidence |
| --- | --- | --- |
| PROD-001 health and public pages | PASS | Health 200; `/login` and `/register` returned 200 at desktop/mobile widths with no page overflow. |
| PROD-002 signed-out protected routes | PASS | All seven protected routes redirected to `/login`; no protected content was exposed. |
| PROD-003 authenticated host login | BLOCKED | Seeded QA credentials were rejected with 401. |
| PROD-004–PROD-021 authenticated route, tab, chat, rewards, accessibility, keyboard, image, and polling cases | BLOCKED | Require a valid disposable production QA session. No live state was manufactured. |
| PROD-022 unauthenticated APIs | PASS | `/api/v1/activities`, `/api/v1/rewards`, and `/api/chat/conversations` returned 401; `/api/users/me` returned 405 because GET is not supported. No user data returned. |
| PROD-023 history navigation | BLOCKED | Requires authenticated navigation. |
| PROD-024 second-persona isolation | BLOCKED | Second documented QA account also returned 401. |
| PROD-025 existing unread/invitation/accessibility states | BLOCKED | No authenticated session was available to inspect these safely. |
| AUTH-003 wrong password | PASS | Remained on `/login` and showed a human-readable error without creating a session. |

The only browser console error observed was the expected 401 generated by the wrong-password test. No 5xx response, uncaught page exception, hydration error, or page-level overflow was observed on tested public surfaces.
